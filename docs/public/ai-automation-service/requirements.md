## 0. 現在の結論

shinjin.ai は、横原聖八が直契約で受ける **中小企業向けAI業務自動化サービス** として立ち上げる。

最初に作るべきものは、詳細なSaaSではなく **直受け用のLPサイト**。LPの役割は、検索・SNS・紹介・スカウト媒体から来た見込み客に対して「この人なら、自社の手作業を見てAI化してくれそう」と思ってもらい、問い合わせにつなげること。

| 決定事項 | 方針 |
|----------|------|
| 主導線 | shinjin.ai のLPから直問い合わせ |
| 契約方針 | 直契約を基本にする。エージェント経由は主導線にしない |
| 初期商品 | 初期構築1人月100万円〜で、1業務を1ヶ月で自動化する受託案件 |
| 価格軸 | 初期構築1人月100万円〜 / 月額保守は初期構築の15% |
| 対応地域 | 初期は奈良・大阪近郊。ドメイン理解のため対面推奨 |
| LPトーン | 親しみやすく、少しラノベ風。ただし法人が発注できる信頼感は保つ |
| 公開基盤 | Cloudflare Pages想定 |
| LP制作 | ホームページ自動販売機で生成し、自社実績としても使う |

## 1. サービス概要

| 項目 | 内容 |
|------|------|
| **サービス名** | shinjin.ai（新人AI） |
| **英語名** | Shinjin AI |
| **ドメイン** | shinjin.ai（取得予定。公開前にレジストラで最終確認） |
| **屋号** | オフィセイト |
| **運営者** | 横原聖八（一人運営） |
| **コンセプト** | 中小企業のバックオフィスに「新人AI」を配属する |
| **キャッチコピー** | 社長〜！今年の新人はAIにしていいですか？ |
| **事業形態** | BtoB / 請負型 + 月額保守 |
| **商圏** | 初期は奈良・大阪近郊を主軸。Google Meetも可だが、対面ヒアリング推奨 |
| **主要顧客** | 管理部・総務部・経理部の手作業が多い中小企業 |

### 一言で言うと

中小企業の経理・総務・管理部門に残っている転記、集計、確認、メール、帳票処理を、AI・RPA・API連携・専用Webシステムで自動化するサービス。

### LPで伝える提供価値

> 新人社員を1人採用する代わりに、休まず・辞めず・ミスを減らし続ける「新人AI」をバックオフィスに配属する。

### 顔の見えるサービスにする

一人運営であることは弱みでもあるが、初期のshinjin.aiでは **横原聖八本人が直接見る** ことを価値にする。LPでは顔写真・実名・屋号を前面に出し、発注前に「誰が来るのか」が分かる状態にする。

ただし、規模の大きすぎる全社DXや複数部門同時展開は無理に受けない。最初は1社1業務を丁寧に自動化する。

## 2. ポジショニング

shinjin.ai は、汎用SaaSではなく **業務を見て、個別に作るAI自動化屋** として打ち出す。

| 比較対象 | 相手の特徴 | shinjin.ai の立ち位置 |
|----------|------------|------------------------|
| 汎用SaaS | 標準業務には強いが、現場固有の例外に弱い | 現場の業務フローに合わせてフルスクラッチで作る |
| RPAツール販売会社 | ツール導入が中心 | AI判断・API連携・Webシステムまで含めて作る |
| DXコンサル | 提案や設計が中心になりやすい | 要件定義から実装・運用保守まで一人で担う |
| フリーランスエンジニア | 開発単体の受託になりやすい | 業務理解と自動化設計を含めて価値提供する |
| AI研修会社 | 使い方を教える | 実際に業務が回る仕組みを納品する |

### 肩書き

LP・SNS・スカウト媒体では、以下の表現を使う。

> 中小企業のバックオフィス業務を、AI・RPA・Webシステムで自動化するフルスタックエンジニア

または、

> AI業務自動化・LLM/RAG・フルスタック開発を、要件定義から運用まで一気通貫で支援します

## 3. ターゲット顧客

### 企業プロフィール

| 条件 | 詳細 |
|------|------|
| 所在地 | 奈良・大阪近郊。将来的には全国フルリモートも対応 |
| 年商 | 5億円以上を目安 |
| 従業員数 | 30名以上を目安 |
| バックオフィス | 管理部・総務部・経理部に3名以上 |
| 予算の考え方 | 新人1人分の採用費・人件費・教育コストを、新人AIの初期構築・保守へ振り替える判断ができる |
| 既存接点 | HP制作顧客、紹介、地域の中小企業、SNS流入 |

### 初期に優先する部門

最初のLPでは、部門を1つに絞りすぎず **経理・総務・管理部門** を掲げる。ただし、最初のデモと営業トークでは **経理・営業事務の定型処理** を優先する。

| 優先 | 部門 / 業務 | 理由 |
|------|-------------|------|
| 1 | 経理の請求書・経費・入金関連 | 金額換算しやすく、ROIを説明しやすい |
| 2 | 営業事務の見積・受発注・顧客情報更新 | 転記・確認・メール処理が多く、自動化しやすい |
| 3 | 総務の勤怠・社内通知・備品管理 | リスクを抑えつつ小さな改善を積みやすい |
| 4 | 管理部門のレポート集約 | Excel / スプレッドシート / PDF / メールの統合処理と相性が良い |

AIの判断ミスが重大事故につながる業務は、初期サービスでは完全自動化を急がない。まずは人間確認を残した半自動化から始める。

### 決裁者

| 役割 | 関心 |
|------|------|
| 社長 | 人件費削減、採用難、退職リスク、属人化解消 |
| 管理部長 | 月次作業の負担削減、ミス削減、引き継ぎ負荷の軽減 |
| 経理責任者 | 請求書・仕訳・入金消込・経費精算の効率化 |
| 総務責任者 | 勤怠、契約、備品、社内通知、問い合わせ対応の効率化 |

### 顧客の痛み

- 人間中心に設計されておらず、手作業の都合で継ぎ足された業務フローが多い
- 担当者しか分からないExcelや手順が多い
- 請求書、注文書、メール、PDF、管理画面の転記が多い
- 採用しても教育に時間がかかり、辞めるリスクがある
- SaaSを入れても、自社の業務フローと微妙に合わない
- 社内にAIやAPI連携を設計・実装できる人がいない
- DXやAI導入をしたいが、何から始めるべきか分からない

## 4. サービス内容

### 何をするか

企業のバックオフィス業務を、業務フローの整理から実装・運用保守まで一気通貫で自動化する。

### 技術アプローチ

| アプローチ | 内容 |
|------------|------|
| RPA的自動化 | Playwright等でブラウザ操作を自動化。既存システムをそのまま操作 |
| API連携 | freee、マネーフォワード、kintone等のSaaS間を繋ぐ |
| AIエージェント | Claude/GPTに分類・抽出・判断補助をさせる |
| RAG / ナレッジ検索 | 社内規程、FAQ、過去対応履歴を検索可能にする |
| カスタムWebシステム | 業務に合わせた専用ツールをゼロから構築 |
| データパイプライン | CSV、PDF、Excel、メール、DB、API間の変換・同期 |
| PC丸ごとAI化 | AIに1台のPCを与え、ブラウザ・Office等を人間同等に操作させる |

### 自動化対象部門と想定業務

| 部門 | 自動化候補の業務例 |
|------|-------------------|
| **経理部** | 請求書処理、仕訳入力、経費精算、入金消込、月次決算資料作成 |
| **総務部** | 勤怠集計、社会保険手続き、備品管理、契約書管理、社内通知配信 |
| **管理部** | 採用応募者管理、入退社手続き、各部門レポート集約、データ転記全般 |
| **営業事務** | 見積書作成、受発注入力、顧客情報更新、問い合わせ一次分類 |

### 初期に受けやすい業務

| 業務タイプ | 例 | 方針 |
|------------|-----|------|
| マニュアル化済み業務 | 手順書通りの入力、確認、転記 | 最優先。AIよりも自動化設計で成果が出やすい |
| 定型データ処理 | CSV、Excel、PDF、メール、フォーム | 初回デモに向く |
| AIが得意な補助業務 | 分類、要約、抽出、文章案作成 | 人間確認を残して導入する |
| 既存画面操作 | 管理画面、SaaS、社内Webシステム | Playwright等で既存環境を活かす |

### 初期に慎重に扱う業務

| 業務タイプ | 理由 | 対応 |
|------------|------|------|
| 判断ミスが大きな損害につながる業務 | 会計・法務・医療・与信など | 完全自動ではなく、人間承認を残す |
| 電話などリアルタイム対外対応 | 品質・責任範囲が読みづらい | 初期LPでは主商品にしない |
| 現場で手順が固まっていない業務 | 自動化以前に業務整理が必要 | 先に業務棚卸し・PoCから始める |

### 自動化レベル

| レベル | 内容 | 例 | 対応時期 |
|--------|------|-----|----------|
| Lv1 | 定型データの転記 | 請求書 → 会計ソフト入力 | 現在対応可能 |
| Lv2 | ルールベースの判断+処理 | 仕訳の自動分類、承認ルート振り分け | 現在対応可能 |
| Lv3 | 非定型データの読み取り+処理 | 手書きFAX、形式がバラバラな注文書処理 | 次世代AIで対応範囲拡大 |
| Lv4 | 人間的判断を伴う業務 | 与信判断、クレーム一次振り分け | 将来的に対応 |
| Lv5 | 対外コミュニケーション | 取引先への発注メール、電話対応 | 将来的に対応 |

### 初回に売るべき小さな商品

最初から全社DXを売らない。LPでは、問い合わせの心理的ハードルを下げるために **1業務だけ自動化** を前面に出す。

| 商品 | 内容 |
|------|------|
| 新人AIお試し配属 | 1業務を選び、1ヶ月で自動化する初期導入 |
| 対象 | 転記、集計、メール分類、PDF読み取り、SaaS連携など |
| 成果物 | 動く自動化システム、操作手順、保守体制 |
| 目的 | 小さく成果を見せて、追加業務と保守契約につなげる |

## 5. ビジネスモデル

### 価格体系

| 項目 | 金額 | 備考 |
|------|------|------|
| **初回相談** | 無料 | 対面1回まで無料。Google Meetも可 |
| **業務診断 / PoC** | 個別見積 | プロトタイプ作成、PoC開発など実作業が発生する段階から有料 |
| **初期構築** | 1人月100万円〜 | 1案件1ヶ月が基本。規模により最大3ヶ月 |
| **月額保守** | 初期構築の15% | AIチューニング・業務変更対応・障害復旧を含む |

### 価格の考え方

- 初期構築は「新人1人分の採用・教育・引き継ぎコスト」と比較して安く見せる
- 追加のIT投資ではなく、人件費・採用費・教育コストの振替として提案する
- 初期構築1人月100万円〜は本音の価格として出す。他のコンサルより安く、実装まで含むことを価値にする
- 月額保守は「新人AIの教育係・改善係」として位置づける。新人1人を雇う代わりにランニングコストを回してもらう
- AIは日進月歩なので、納品時点の精度で固定せず、運用保守で継続的にチューニング・例外追加・改善を回すことが重要
- 安売りではなく、削減できる人件費・ミス・属人化リスクから逆算する
- LPでは月80万円の継続契約は出さない。あくまで初期構築 + 月額保守を主商品にする

### ROI訴求

```text
大阪の新卒事務職1人の年間コスト
（給与 + 会社負担 + 採用教育 + 管理工数） ≒ 530〜560万円
    ↓
新人AIの年間コスト（初期構築1人月100万円 + 初期構築の15% × 12ヶ月） = 280万円
    ↓
人件費の約半額。
しかも、退職リスクなし・24時間稼働・改善し続ける。
```

### 新人さん vs 新人AI 価格比較

LPでは「追加のIT投資」ではなく、「新人1人分の採用費・人件費・教育コストの振替」として見せる。
完全な人間代替ではなく、経理・総務・管理部門の定型業務を新人AIに任せる前提の営業用概算にする。

#### 比較の前提

- 比較対象は、新卒の事務的職業に固定する
- 大阪労働局「令和7年3月新規学校卒業者初任給情報」では、事務的職業・大学卒の初任給目安は252千円
- 厚生年金は18.3%を事業主と被保険者で折半、協会けんぽ大阪府の令和8年度健康保険料率は10.13%、雇用保険の令和8年度一般事業の事業主負担は8.5/1,000
- 新人さん側は、月給だけでなく、賞与、残業代、交通費、法定福利費、採用費、面接工数、教育/OJT、上長レビュー、PC/SaaS/席、引き継ぎ・退職リスクまで含める
- LP上の概算では、社会保険の会社負担、交通費、福利厚生、採用教育の端数を含めて、給与・賞与・交通費等の20%を会社負担として置く
- 新人さん1年目は、給与・賞与・交通費等360万円 + 会社負担72万円 + 採用教育/OJT/管理/備品130万円 = 約560万円で試算する
- 新人さん2年目は、給与・賞与・交通費等390万円 + 会社負担78万円 + OJT/管理/備品60万円 = 約530万円で試算する
- 新人AIは初期構築100万円、月額保守は初期構築の15% = 月15万円で試算する。2年目は同一業務の保守のみで見る
- 対象業務はAIに有利な条件に寄せる。月間件数が多い、繰り返しが多い、繁忙期に集中する、夜間・休日に処理できる、手順化済み、例外だけ人間確認に回せる業務を選ぶ
- 新人AIは対象業務が回る状態なら24時間365日の定型処理に使える。遅刻・欠勤・教育の個人差・早期退職・異動・引き継ぎ漏れなど、新人採用時に起きやすい不確実性も抑えられる

| 比較対象 | 1年目 | 2年目 | 見せ方 |
|---|---:|---:|---|
| 新人さん | 約560万円 | 約530万円 | 新卒初任給を基準に、賞与、残業代、交通費、会社負担、採用費、教育/OJT、管理工数、備品/SaaSまで含める |
| 新人AI | 280万円 | 180万円 | 初期構築100万円 + 月額保守15万円 × 12ヶ月。2年目は同一業務の保守継続のみ |
| 差額目安 | 約280万円削減 | 約350万円削減 | AIに有利な定型業務を置き換えられる場合の営業用概算。削減だけでなく、退職リスク・属人化・ミス削減・24時間365日稼働も合わせて訴求 |

#### 今回の比較条件

- 比較対象は新卒にする
- 新人さんにかかる費用は、月給、賞与、残業代、交通費、採用費、教育工数、上長レビュー、備品/SaaSなど実際にかかる費用を全部含める
- 対象業務はAIに有利めに置く。件数が多く、繰り返しが多く、夜間・休日にも処理でき、例外だけ人間確認に回せる業務を選ぶ
- 新人AIの2年目は保守のみで見る。追加業務の初期構築は別見積にする
- 失敗時の損失、二重チェック工数、属人化・退職時の引き継ぎリスク
- LP表示では、費用比較セクションの写真と比較表を左右2カラムにせず、写真、指標、比較表を横幅いっぱいに縦積みする
- 比較表は「比較対象」列を少し広めに取り、「新人さん」「差額目安」が途中で改行されないようにする
- ワークフロー図の下に置くイメージ画像は、上のフローカードと密着させず、余白を明確に取る

### 案件の流れ

```text
1. 無料相談 / 初回ヒアリング（対面1回まで無料）
   └ 現在の手作業・困りごと・対象部門を聞く
   └ 自動化できそうな業務を1〜3個に絞る
   └ Google Meetも可。ただし初回は対面推奨

2. 現場ヒアリング（出向1〜2日）
   └ 現場の業務フローを観察・聞き取り
   └ 入力・処理・出力・例外対応を整理

3. 初期構築（自宅 約1ヶ月）
   └ AI / RPA / API / Webシステムを組み合わせて構築
   └ 顧客環境に合わせたカスタム実装

4. 導入（出向1〜2日）
   └ 現地でセットアップ・動作確認
   └ 担当者へのレクチャー

5. 運用保守（リモート）
   └ 障害対応、業務変更対応、AIチューニング
   └ 成果が出たら次の業務を追加自動化
```

## 6. LPサイト要件

### LPの目的

shinjin.ai のLPは、サービス説明ページではなく **直受け案件を獲得する営業ページ** として作る。

| 項目 | 方針 |
|------|------|
| 第一目的 | 問い合わせ・無料相談につなげる |
| 第二目的 | 横原聖八の市場価値と信頼性を見せる |
| 第三目的 | ホームページ自動販売機で生成した自社実績として使う |
| 訪問者 | 社長、管理部長、経理責任者、紹介者、スカウト担当者 |
| CTA | 「無料相談する」「自動化できる業務を相談する」 |

### ブランドトーン

| 項目 | 方針 |

## 7. 競争優位性・参入障壁

### 大手が参入しにくい理由

1. **市場が小さい** — 中小企業ごとの個別業務はSaaS化しにくい
2. **標準化できない** — 企業ごとに業務フロー・使用ソフト・例外処理が違う
3. **現場作業が必要** — 出向してヒアリング・セットアップする必要がある
4. **小回りが必要** — 1社ごとの細かい修正に付き合う必要がある

### 非エンジニアが参入しにくい理由

| 障壁 | 横原の強み |
|------|------------|
| フルスクラッチ実装力 | 20年の開発経験。JS/PHP/Python/TS/SQLに対応 |
| API連携・データパイプライン | REST API設計、DB設計、ETLの実務経験 |
| AI活用 | OpenAI API実装、RAG構築、プロンプト設計の実務経験 |
| RPA / ブラウザ自動化 | Playwright等で既存システムを操作できる |
| インフラ・セキュリティ | サーバー構築、ネットワーク、秘密情報管理、権限設計 |
| デバッグ・障害対応 | 自動化が壊れたときに原因を追って直せる |
| 業務理解力 | HP制作を通じた多業種の中小企業業務への理解 |
| ROI設計 | 単なるAI導入ではなく、人件費・手作業・保守費用の釣り合いから提案できる |

### 現時点でLPに書いてよい実績表現

- 20年以上のIT経験を持つフルスタックエンジニア
- Webアプリ、Webシステム、業務システム、インフラ、DB、AI活用まで幅広く対応
- 草案、設計、実装、保守まで一人で完結できる
- AIを単なるチャット用途ではなく、Issue・API・DB・スプレッドシート・Slack通知・公開フローまでつないで業務効率化へ落とし込む
- メール、PDF、既存DB、FileMaker、Slack、人間確認を組み合わせ、例外だけ人が見る業務フローを設計できる
- 音声、画面、DOM、Vision LLMを組み合わせ、現場の曖昧な依頼を構造化できる
- AI判定をそのまま信じず、ルール判定・人間確認・データ検証・失敗時の安全網を組み合わせる
- 実績表現はGitHub証跡と照合し、誇張せずに見せる
- ドメイン全体を理解し、ROIとWin-Winな関係を重視して提案する

### 言いすぎないこと

- ソロ運営のため、大規模案件や同時並行の大量案件は受けすぎない
- AIで何でも完全自動化できるとは言わない
- 判断ミスが重大事故につながる業務では、人間確認を残す
- 非公開顧客・非公開リポジトリの詳細はLPに出さない

### LPで強く見せるべき実績の型

- 作ったものの画面
- 処理前後の比較
- 削減できる作業時間
- 人間確認を残した安全な運用設計
- 「一度作って終わり」ではなく、保守で改善し続ける点
